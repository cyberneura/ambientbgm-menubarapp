# AmbientBGM Menubar

A macOS menu bar app that does nothing more than open ambientbgm.com in a WKWebView inside an NSPopover.
`Sources/*.swift` (the app itself, `main.swift`, and the generated `ThirdPartyNotices.swift`) are compiled directly with `swiftc`
(there is no Xcode project and no SwiftPM).
This is a public repository, so the README, this file, and UI strings in the code are written in English.

It originally lived in `menubarapp/` of `cyberneura/ambientbgm` (split out in CYBERNEURA-DEV-859).
The web player itself lives in that repository.

## Build

```shell
scripts/make-app.sh     # dist/AmbientBGMMenubar.app (universal, unsigned)
scripts/make-dmg.sh     # dist/AmbientBGMMenubar_<version>_universal.dmg
```

- Do not commit the `.icns`. `make-app.sh` builds it from `resources/AppIcon.png` every time
- `Info.plist` is produced from `packaging/Info.plist` by replacing `__VERSION__` with `VERSION`
- **It cannot be built on Linux** (Cocoa / WebKit). Rely on the PR CI test job (macOS) for verification

## License notices

- The app itself is MIT (`LICENSE`). The list of bundled libraries is in `THIRD-PARTY-NOTICES.txt`
- `THIRD-PARTY-NOTICES.txt` and `Sources/ThirdPartyNotices.swift`, which embeds it into the binary, are
  generated by `scripts/generate-third-party-notices.sh`. Do not edit them by hand
- Currently only Apple frameworks (Cocoa / WebKit) are used, and no third-party libraries are bundled.
  The script fails if a Package.swift / Package.resolved / Xcode project appears, or if anything other
  than an Apple framework is imported. **When adding a dependency, extend the script to write out its
  notice, rerun it, and commit the generated files** (the PR test job detects stale output with `--check`)
- They are shown in an NSAlert via "Third-Party Licenses…", right below About in the right-click menu

## Release

**Just bump `VERSION` on main** (`scripts/release.sh [patch|minor|major]`).
`.github/workflows/release.yml` only checks "has a Release for this version been published yet",
and if not, runs test → signed and notarized build → publish. On PRs only the test job runs.

- Signing and notarization need the repository secrets `APPLE_CERTIFICATE` / `APPLE_CERTIFICATE_PASSWORD` /
  `APPLE_SIGNING_IDENTITY` / `APPLE_ID` / `APPLE_PASSWORD` / `APPLE_TEAM_ID`.
  If any are missing, the build job stops at its first step (so that an unsigned dmg is never published)
- The Homebrew cask is `Casks/ambientbgm-menubar.rb` in `cyberneura/homebrew-tap`.
  The tap checks the latest Release every hour and updates itself

## How the chat UI is hidden

The app appends `AmbientBGMApp/<version>` to the User-Agent and opens the page with `?no-chat=1`.
ambientbgm.com (`chatVisibility.ts` in the webapp) hides the chat widget if either is present.
If you change the token name, keep it in sync with the webapp.

## Mac App Store

Distribution through the Mac App Store is being considered for the future. That would additionally require
App Sandbox entitlements (`com.apple.security.app-sandbox` + `com.apple.security.network.client`) and
signing with an Apple Distribution certificate (the current workflow only handles Developer ID distribution).
